# 롱폼 편집

촬영본 → 완성 롱폼 MP4. 사람이 승인하는 문은 **세 개**다: ① 구성안 ② 레퍼런스 분석·에셋 확인 ③ 편집본 피드백.
문을 건너뛰지 않는다. 승인 전에는 다음 단계 파일을 확정하지 않는다.

## 도구

모든 스크립트는 이 스킬 폴더의 실행기 `bin/lf`로 돌린다. 아래에서 `lf`는 `"<이 SKILL.md가 있는 폴더>/bin/lf"`다.

| 명령 | 하는 일 |
|---|---|
| `lf doctor` | 설치 점검. **처음 쓸 때 먼저 돌린다.** 종료 코드 3이면 미설치 → 레포의 `install.sh` 실행(README 참고) |
| `lf new_project "<이름>"` | 프로젝트 폴더 4개 생성, 마지막 줄에 경로 출력 |
| `lf sd_backup --list` / `--project … --card … --label …` | SD카드 감지·백업·MD5 검증 |
| `lf transcribe <파일> <출력.json> --glossary <용어.txt>` | 단어 단위 전사(mlx-whisper, 로컬) |
| `lf transcript_lines` · `plan_script` · `plan_verify` | 줄 단위 전사본, 예상 스크립트, 구성안 검증 |
| `lf ref_analyze` | 레퍼런스 컷 호흡·라우드니스·프레임 시트 |
| `lf sync` | 멀티캠·외부 사운드 싱크(오디오 상호상관) |
| `lf fillers` | 음·어·반복·다시 말하기·긴 침묵 후보 |
| `lf color_match` | 캠 간 색 맞춤 |
| `lf make_subs` · `export_srt` | 컷 타임라인 자막 생성, SRT 내보내기 |
| `lf render` | 편집결정 → MP4 (+ `--xml` 프리미어/다빈치 XML, `--height 540` 확인용) |
| `lf qc` | 렌더 결과 수치 검수 + 컷 이음새 시트 |
| `lf shorts/…` | 쇼츠 제작 도구(롱폼에서 쇼츠 뽑기 — `shorts-maker` 스킬) |

모든 스크립트는 `lf <이름> --help`로 사용법이 나온다. 설정(`~/.longform-edit/config.json`)의 `projects_root`가
프로젝트들을 모아 두는 폴더, `feedback_log`가 프로젝트를 넘어 누적되는 피드백 장부다.

## 프로젝트 폴더 규칙 (사용자 규칙 — 반드시 지킨다)

하나의 프로젝트 = 하나의 폴더. 그 안에는 **딱 네 개**만 둔다.

```
<projects_root>/<프로젝트 이름>/
  촬영본/    카메라·사운드별로 정리한 원본. 읽기만 — 수정·이동·삭제 금지
    A캠/<촬영일>_<카드이름>/…   B캠/…   사운드/…
  편집본/    렌더해서 뽑은 완성 영상만: <이름>_1차 편집본.mp4, _2차 편집본.mp4 …
  편집자료/  그 외 편집 진행 자료 전부
    프로젝트정보.json(7문항 답)  기획안/  레퍼런스/(영상·분석)  전사/  구성안/  시트/
    싱크.json  필러후보.md  에셋확인.md  편집결정.json  자막.json  색보정.json
    <이름>_타임라인.xml  <이름>_자막.srt  중간저장/  렌더캐시/  QC/  로그/  백업로그/
  에셋/      폰트/ 로고/ BGM/ 효과음/ 그래픽/(타이틀·엔딩 등)
```

- 사용자가 파일을 다른 곳에 줬으면 알맞은 폴더로 **복사**(이동 X)해서 시작한다. 수십 GB 원본은 복사 전에 묻는다.
- XML·SRT·QC·중간 렌더는 절대 `편집본/`에 두지 않는다.
- macOS 한글 파일명은 NFD일 수 있다 — 비교할 땐 `unicodedata.normalize("NFC", …)`, 찾을 땐 와일드카드로 나열 후 정규화.

## 시간 기준: 마스터 타임

외부 사운드 파일의 시간이 **마스터 타임**이다(없으면 메인 카메라 오디오). 전사·구성안·컷의 in/out은 전부
마스터 타임 초. 카메라 영상은 `싱크.json`의 `video_offset`으로 환산: `cam_t = master_t - video_offset`.

## STEP 0. 질문 7개 — 작업 전에 한 번에 묻는다

아래 7개를 **번호 그대로** 한 메시지로 묻는다. 사용자가 이미 말한 항목은 "이미 받은 것"으로 표시하고 다시 묻지 않는다.

1. 프로젝트 이름과 촬영 기획안 있나요? (없다면 어떤 촬영본인지 짧게 소개해주세요)
2. 동시에 촬영된 카메라 컷이 몇 개 있나요?
3. 레퍼런스영상 유튜브 링크 또는 영상파일이 있나요?
4. 완성본 길이는 얼만큼이 좋을까요?
5. 영상에 넣어야 할 타이틀, 로고, 자막 폰트, 정해진 색상, 트랜지션, 엔딩대판, 배경음악 등 편집 에셋이 있을까요? (없으면 기본으로 진행합니다)
6. 마지막 마무리를 프리미어, 파이널컷, 다빈치, 캡컷 중에 어디서 하고 싶으신가요?
7. 편집본으로 원하는 영상 화질이 있나요? (없다면 촬영본과 동일한 사이즈와 화질로 진행하고, 1차본은 50% 화질로 렌더하겠습니다)

답을 `편집자료/프로젝트정보.json`의 `answers`에 저장한다. 답에 따라:

| 답 | 반영 |
|---|---|
| 1 기획안 | `편집자료/기획안/`에 복사. 고유명사·용어를 `기획안/용어.txt`로 뽑아 전사 힌트·검수에 쓴다 |
| 2 카메라 수 | 1대면 싱크 생략(외부 사운드만 맞춤), 점프컷은 줌으로 숨김. 2대 이상이면 멀티캠 컷 섞기 |
| 3 레퍼런스 | 유튜브 링크면 **다운로드 허락을 따로 받고** `yt-dlp`(venv)로 720p를 `편집자료/레퍼런스/`에. 없으면 포맷별 기본 골격 |
| 4 길이 | 구성안 목표 길이. 없으면 레퍼런스 길이, 그것도 없으면 촬영 분량의 30~40% 제안 |
| 5 에셋 | `에셋/`으로 복사 후 편집결정 `style`·`logo`·`audio.bgm/sfx`에 반영. 없으면 **기본 자막**(아래) |
| 6 마무리 툴 | 프리미어·다빈치 → `render --xml`(FCP7 XML) + SRT. 파이널컷·캡컷 → MP4 + SRT(파이널컷은 XML 직접 불가, 자막은 SRT 가져오기) |
| 7 화질 | 지정 없으면 최종 = 촬영본과 같은 크기. **1차본은 540p(`--height 540`), 2차본부터 최종 화질(보통 1080p)** |

질문을 기다리는 동안 할 수 있는 건 먼저 한다: SD카드 백업, 촬영본 확인(ffprobe), 오디오 추출·전사(백그라운드).

## STEP 1. SD카드 백업 + 프로젝트 폴더

1. `lf new_project "<프로젝트 이름>"` (이름을 아직 모르면 임시 이름으로 만들고 나중에 폴더 이름만 바꾼다)
2. `lf sd_backup --list` — 꽂힌 카드와 추정 카메라(소니·캐논·DJI·고프로·사운드…)를 보여 주고 라벨(A캠/B캠/사운드)을 확인받는다.
   카드가 하나고 추정이 분명하면 그대로 진행해도 된다.
3. `lf sd_backup --project <경로> --card /Volumes/<카드> --label A캠` (카드마다). 백그라운드로 돌리고 진행 상황을 짧게 알린다.
4. 끝나면 `편집자료/백업로그/`의 `all_verified`를 확인해 보고한다. **실패가 있으면 "카드를 포맷하지 마세요"라고 분명히 말한다.**
   카드는 절대 지우거나 포맷하지 않는다(사용자가 직접 한다).
5. 촬영본이 카드가 아니라 폴더로 오면 `촬영본/<라벨>/`로 복사한다.
6. `ffprobe`로 각 파일 길이·해상도·fps·오디오 채널을 표로 정리한다. fps가 섞여 있으면 보고한다.

## STEP 2. 전사 + 기획안 검수 + 레퍼런스 분석 + 구성안 → **문 ①**

**상세 절차는 `references/구성안_절차.md`** (레퍼런스 분석 → 촬영본 전사·화자 구분 → 기획안 대조 → 소재·제외 구간 →
STEP 5 흐름 승인에서 멈춤 → 구성안_N차 + 예상 스크립트 → 자동 검증 → 전달). 요약:

1. 전사: `lf transcribe 촬영본/<사운드> 편집자료/전사/전사.json --glossary 편집자료/기획안/용어.txt`
2. **기획안 검수**: 전사본을 기획안·정보(이름·숫자·용어)와 대조해 오인식을 고치고 `편집자료/전사/검수.md`에 남긴다.
3. 레퍼런스: `lf ref_analyze 편집자료/레퍼런스/<영상> --out 편집자료/레퍼런스/분석/` — 시트 이미지를 **직접 열어 보고**
   자막 위치·크기·색, 강조자막 빈도, 줌인/줌아웃 빈도, 효과음 지점 유형, BGM 분위기, 전환 방식을 `분석/관찰.md`에 적는다.
4. **레퍼런스 구성대로** 편집 구성안을 쓴다: `편집자료/구성안/구성안_1차.md` (형식은 references/구성안_절차.md STEP 6).
5. 구성안을 보여주고 **승인 받는다.** 수정 요청이 오면 `_2차`로 반영 후 다시 확인.

## STEP 3. 레퍼런스 분석·에셋 확인 → **문 ②**

`편집자료/에셋확인.md`에 정리해서 보여주고 승인 받는다:
- 레퍼런스 요약(평균 컷 길이, 분당 컷 수, 라우드니스, 자막 스타일, 강조자막·줌·효과음 빈도, 로고 위치)
- 쓸 에셋: 폰트 파일, 색상 코드, 자막 디자인, 로고(투명 PNG?), 타이틀·엔딩, BGM·효과음 목록. 에셋이 없으면 기본값을 그대로 적는다.
- 빠졌거나 레퍼런스와 충돌하는 것은 질문으로 올린다.

**기본 자막(에셋 없을 때)**: 프리텐다드 Bold, 흰 글자, 검정 외곽선(1080p 기준 4px), 살짝 그림자(2px, 50% 검정), 하단 중앙.
`style`을 비워 두면 렌더러가 이 값을 쓴다(`~/.longform-edit/fonts/Pretendard-*.otf`).
강조 자막은 `styles.강조`(기본 제안: 노랑 `#FFE14D`, 1.2배 크기)로, 레퍼런스에 맞춰 바꾼다.

## STEP 4. 싱크 + 컷편집 (구성안대로, 레퍼런스 호흡으로)

1. 싱크: `lf sync --master 촬영본/사운드/<파일> --cam A=촬영본/A캠/<파일> --cam B=… --out 편집자료/싱크.json`
   - `confidence` < 4 이거나 `drift_ms` > 40이면 프레임 추출로 박수·입모양을 직접 확인하고 원인을 보고(드리프트면 구간별 싱크).
   - 외부 사운드가 없으면 `--master`에 메인 카메라.
2. 지울 후보: `lf fillers 편집자료/전사/전사.json --out 편집자료/필러후보` → 음·어, 같은 말 반복, 다시 말하기(NG), 긴 침묵.
   ●(확실)는 지우고, ○는 문맥을 보고 판단(리액션 "아~"는 살릴 수 있다). 다시 말한 부분은 **마지막 테이크**를 쓴다.
3. `편집자료/편집결정.json` 작성 — 형식은 `references/편집결정_예시.json`.
   - 컷 경계는 **단어 '끝' 시각 + 0.08~0.15초**, 시작은 단어 시작 − 0.05초. 단어 시작으로 끊으면 말꼬리가 잘린다.
   - 평균 컷 길이를 레퍼런스의 ±25% 안으로. **멀티캠이면** 말하는 사람·리액션 기준으로 캠을 섞고, 같은 캠이 8초 넘게 이어지지 않게,
     리액션은 0.5~1초 여유를 둬서 호흡을 맞춘다. **단일캠이면** `zoom`(1.0~1.3)을 교대로 줘서 점프컷을 숨긴다.
   - 각 컷에 `note`로 구성안 챕터를 적는다(피드백 때 위치 찾기용).

## STEP 5. 색·구도·사운드 보정

- 색: `lf color_match 편집자료/편집결정.json --ref A --out 편집자료/색보정.json` (기준 캠 = 레퍼런스 톤에 가장 가까운 캠)
- 구도: 인물 눈높이·헤드룸이 일정하도록 `zoom/cx/cy` 조정(프레임 시트로 확인).
- 사운드: `audio` 블록 — `voice_lufs`(기본 -16, 레퍼런스 라우드니스에 맞춤), `denoise`(6~20), `highpass`(80Hz).

## STEP 6. 자막 · 강조자막 · 줌 · 효과음 · BGM

1. `lf make_subs 편집자료/편집결정.json 편집자료/전사/전사.json --out 편집자료/자막.json`
2. `자막.json`을 **통독하며 STT 오인식·고유명사를 교정**한다(검수.md 반영). 분절 규칙은 레퍼런스 관찰 우선,
   근거가 없으면 기본 분절 규칙 v3.1(강결합 유지·1~2자 파편 금지·문장부호 금지 — `vendor/shorts-automation/PROCESS.md`).
3. 레퍼런스 화면을 참고해 넣는다(빈도는 `분석/관찰.md`의 분당 횟수에 맞춘다):
   - **강조 자막**: 핵심 단어·펀치라인 자막 항목에 `"style": "강조"`. 남발 금지(레퍼런스보다 많으면 줄인다)
   - **줌인/줌아웃**: 컷에 `zoom`→`zoom_to`(예: 1.0→1.18 천천히 줌인, 1.3→1.0 줌아웃). 강조 발언·웃음 포인트에
   - **효과음**: `audio.sfx` `{"file","at"(타임라인 초),"gain_db"}` — 전환·강조·웃음 유형별로
   - **BGM**: `audio.bgm` 구간별(말할 땐 자동 덕킹). 인트로·본편·아웃트로 분위기를 레퍼런스에 맞춘다
   - 에셋이 없으면 효과음·BGM은 사용자에게 파일을 받거나, 무료 라이선스 음원을 제안하고 허락 후 받는다(출처·라이선스를 에셋확인.md에 기록)
4. 로고·타이틀·엔딩은 `logo`, `CARD` 컷(`mute`)으로.

## STEP 7. 렌더 → 1차 편집본 (540p)

```
lf render 편집자료/편집결정.json --subs 편집자료/자막.json \
   --out "편집본/<이름>_1차 편집본.mp4" --work 편집자료/렌더캐시 --xml --height 540
lf export_srt 편집자료/자막.json --out "편집자료/<이름>_자막.srt"
```
- 7번 답에 다른 조건이 있으면 그걸 따른다. **2차본부터는 `--height`를 빼서 최종 화질(보통 1080p)로.**
- 컷 단위 캐시 — 바뀐 컷만 다시 렌더된다. XML은 `편집자료/`에 남는다(컷 타임라인만, 자막·BGM·색은 MP4에만).
- 렌더 직후 편집결정·자막을 `편집자료/중간저장/편집결정_1차.json`, `자막_1차.json`으로 복사.
- 렌더는 길다 — 백그라운드로 돌리고 PID로 다룬다.

## STEP 8. QC → Finder 열기

1. `lf qc "편집본/<이름>_1차 편집본.mp4" 편집자료/편집결정.json --subs 편집자료/자막.json --out 편집자료/QC/1차 --ref 편집자료/레퍼런스/분석/분석.json`
   — `report.md`의 경고를 전부 해결하거나 사유를 적는다. 이음새 시트는 직접 열어 본다.
2. `open "<프로젝트>/편집본"`으로 Finder를 연다.
3. 레퍼런스 분석 수치와 1차본 QC 수치를 표로 비교해 보여준다.

## STEP 9. 피드백 예측

`feedback_log`(피드백기록.md)를 읽고 이번 편집본에 해당할 법한 피드백을 예측한다:
`예상 피드백 | 근거(과거 기록 날짜·프로젝트) | 해당 위치(타임코드) | 미리 고칠지`. 기록이 없으면 레퍼런스와의 차이로 예측하고 그렇다고 밝힌다.

## STEP 10. 피드백 반영 → 2차·3차 (1080p)

1. 피드백을 **번호 매긴 체크리스트**로 쪼개 `편집자료/피드백_N차.md`에 적는다(애매한 건 먼저 질문).
2. 편집결정·자막을 수정하고 `<이름>_(N+1)차 편집본.mp4`로 **최종 화질** 렌더, 중간저장 스냅샷을 남긴다.
3. **자체 점검**: 항목마다 `반영 위치(타임코드) | 확인 방법 | 결과` — 증거로(프레임 추출, 자막 diff, qc 수치).
   이전 차수에서 맞았던 것이 깨지지 않았는지 `중간저장/`과 diff로 확인.
4. 피드백을 `feedback_log`에 누적(날짜, 프로젝트, 차수, 분류[컷/자막/색/사운드/음악/효과음/그래픽·로고/구성], 요지, 일반화된 규칙).
5. QC 후 Finder로 편집본 폴더를 연다.

## STEP 11. 최종 대조

마지막 차수 후 레퍼런스 수치와 QC 수치를 나란히 — 평균 컷 길이, 분당 컷 수, 라우드니스, 자막 위치/크기,
강조자막·줌·효과음 빈도, 로고, BGM 비중. 크게 벗어난 항목은 고치거나 의도된 차이인지 확인받는다.

## 함정 (겪으면 여기에 추가)

- 컷 끝을 단어 시작 시각으로 잡으면 매 컷 말꼬리가 잘린다 — 단어 끝 + 여유.
- 자막을 같은 파일명으로 재생성하고 프리미어에서 열면 옛 타이밍이 남는다 — 빈 삭제 후 XML 재가져오기.
- `-ss`로 대충 시킹한 원본 프레임으로 판정하지 말 것 — 판정은 렌더된 파일 기준.
- 렌더 중단 시 짧은 파일이 남는다 — qc의 길이 대조가 잡는다. 경고 무시 금지.
- `촬영본/`은 절대 덮어쓰지 않는다. 모든 산출물은 `편집자료/` 또는 `편집본/`.
- SD카드는 백업 검증 전에 빼지 말라고 안내한다. 카드에는 아무것도 쓰지 않는다.
- yt-dlp가 유튜브에서 막히면 `~/.longform-edit/venv/bin/pip install -U yt-dlp` 후 재시도. 그래도 안 되면 references/구성안_절차.md STEP 1.
- 직접 만든 스크립트를 `python3 -I`로 돌리면 같은 폴더 모듈을 못 불러온다 — `-I`는 내려받은 파일을 다룰 때만.
- 이미 컷편집된 ProRes(5분에 8GB)는 복사하지 말고 제자리에서 읽는다(복사가 필요하면 먼저 묻는다).
