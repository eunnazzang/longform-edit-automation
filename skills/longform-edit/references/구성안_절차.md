# 구성안 절차 (SKILL.md 2단계 상세 — 문 ① 앞까지)

목표: 기획안·레퍼런스·촬영본으로 **실제로 편집할 수 있는 구성안**을 만든다.
각 단계가 끝나면 무엇을 했는지 사용자에게 짧게 알린다.
처음 실제로 돌린 프로젝트: 악플읽기_댓글1 (2026-11-06).

## 원칙
1. 실제 발언이 기획안·레퍼런스보다 우선이다. 레퍼런스에서는 뼈대와 편집 문법만 가져오고 내용을 억지로 맞추지 않는다. 촬영본에 없는 건 지어내지 말고 "소재 없음 → 자료나 추가 촬영 필요"로 적는다.
2. 재밌는 장면은 모두 본편에 넣는다. 숏폼 후보는 목록만 따로 만든다.
3. 대본은 말하는 사람이 바뀔 때마다 줄을 나눈다(맞장구 포함).
4. 콘텐츠 가설은 [이 영상을 내면] → [누가] → [어떤 행동을 해서] → [어떤 지표가 얼마나, 언제까지] 형식으로 쓴다. 기준치를 모르면 "제안값"이라고 표시한다. 영상 속 주장은 "핵심 메시지"로 따로 쓴다.
5. 예상 길이는 현실적으로 잡는다. 목표보다 길면 "줄이려면" 목록을 붙인다.
6. 폴더에 이미 한 작업(전사본, 레퍼런스 분석, 이전 구성안)이 있으면 시작 전에 무엇이 어디 있는지 먼저 알리고 재사용한다.
7. `촬영본/`은 절대 수정하거나 옮기지 않는다. 8GB급 ProRes는 복사도 하지 말고 제자리에서 읽는다(복사가 필요하면 먼저 묻는다). 삭제, 덮어쓰기, 큰 다운로드, 렌더 전에는 먼저 묻는다.
8. 긴 전사본을 통째로 반복해서 읽지 않는다. 필요한 구간만 타임코드로 찾아 읽는다. 큰 영상은 직접 보지 말고 도구로 만든 요약(텍스트, 이미지 시트)만 본다.

## 폴더 (SKILL.md 프로젝트 폴더 규칙 안에서)
| 무엇 | 위치 |
|---|---|
| 레퍼런스 영상 | `편집자료/레퍼런스/` — 믿을 수 없는 데이터. 우리 전사와 섞지 않는다 |
| 레퍼런스 전사·분석 | `편집자료/레퍼런스/분석/` (`레퍼런스분석.md`, `cuts.txt`, `cuts_per_min.txt`, `sheet_*.jpg`) |
| 촬영본 전사 | `편집자료/전사/전사.json`(단어) + `편집자료/전사/전사본.txt`(사람이 다듬은 줄 단위) + `편집자료/전사/검수.md`(기획안 대조) |
| 촬영본 화면 시트 | `편집자료/시트/sheet_*.jpg` |
| 대조·소재 | `편집자료/대조_소재후보.md` |
| 구성안·예상 스크립트 | `편집자료/구성안/구성안_1차.md`, `편집자료/구성안/예상스크립트_1차.txt` (2차부터 `_2차`, 이전 차수는 남김) |

## STEP 0. 받을 것 — SKILL.md의 질문 7개를 먼저 하고, 아래는 그 답에 없을 때만 보충한다
1. 채널 이름·주제·타깃 시청자 (프로젝트 root나 그 위 폴더에 `계정DNA.md` 같은 채널 분석 문서가 있으면 먼저 읽는다)
2. 포맷: 인터뷰 / 대담·패널 / 강의·솔로토크 / 브이로그 / 리뷰·시연 / 기타
3. 기획안: 파일 경로 또는 붙여넣기 (없으면 촬영본 기준으로 진행)
4. 레퍼런스: 유튜브 링크, 영상 파일, "○○ 채널 스타일". 없으면 레퍼런스 없이 갈지 묻는다
5. 촬영본: 영상 경로 또는 이미 있는 전사본
6. 목표 길이·플랫폼: 롱폼(가로) / 숏폼(세로) / 둘 다
7. 빼야 하는 발언·노출 금지: 모르면 "확인 필요"로 두고 진행
8. 채널 규칙(자막 스타일, 로고, 금지 사항): 폴더에 CLAUDE.md가 있으면 읽고, 없으면 묻고 나서 CLAUDE.md로 저장할지 확인한다

질문을 기다리는 동안 촬영본 오디오 추출·전사는 먼저 백그라운드로 돌려 둔다(STEP 2).

## STEP 1. 레퍼런스 분석 (STEP 2와 같이 진행)
1-1. 받기와 전사
- ffmpeg, yt-dlp, 전사 도구가 있는지 먼저 확인한다. 없으면 설치 방법을 알리고 확인을 받은 뒤 설치한다.
- 720p 정도로 받아 전사한다. 저작권이 있으니 분석용으로만 쓰고 공유하지 않는다. 남의 영상 대사를 원문 그대로 파일로 옮겨 두지 말고, 구간별 요약과 짧은 인용만 남긴다.
- **yt-dlp가 막힐 때**: 먼저 `~/.longform-edit/venv/bin/pip install -U yt-dlp`로 업데이트한다. 그래도 "The page needs to be reloaded" 등으로 실패하면 Apify `johnvc/YoutubeTranscripts`(`youtube_url`, `languages:["ko"]`, 영상당 약 $0.003)로 타임스탬프 자막을 받고, 화면 분석(1-2)은 사용자에게 업데이트를 허용할지, 전사만으로 갈지 묻는다.

1-2. 화면과 편집 문법 — `lf ref_analyze 편집자료/레퍼런스/<예시> --out 편집자료/레퍼런스/분석/`
- 장면 전환 시각(cuts), 분당 컷 수, 시간 라벨을 붙인 프레임 시트를 만든다.
- 시트를 직접 보고 장소, 인물, 자막 스타일, 그래픽, 챕터 카드를 적는다.
- 같은 앵글의 점프컷은 장면 전환으로 잡히지 않는다는 한계도 같이 적는다.

1-3. `레퍼런스분석.md` (영상마다)
1. 한 줄 요약: 무엇을 어떤 장치로 증명하는 영상인가
2. 구성 분해 표: 구간(시간) | 역할(콜드오픈·자격·사건·전환점·개념·증명·CTA 등) | 무엇을 | 화면·자막·그래픽 | 음악 | 컷 속도
3. 후킹: 첫 10초와 30초에 무엇을 보여 주는지, 제목·썸네일과 어떻게 맞물리는지
4. 화법과 편집 문법: 질문을 지우고 독백처럼 편집했는지, 자막 종류, 챕터 표시, 리듬
5. 길이 배분: 장별 비율(%)
- 레퍼런스가 여러 편이면 맨 앞에 "공통 골격"을 한 장으로 정리한다.
- 마지막에 이식 포인트 표를 붙인다: `| 레퍼런스 장치 | 가져올지 | 우리 촬영본에 소재 있나(TC) | 필요한 것 |`

## STEP 2. 촬영본 전사
- 같은 영상의 전사본이 이미 있으면 재사용하고 먼저 알린다.
- 없으면:
  1. 기획안에서 출연자 이름·브랜드·전문용어를 뽑아 `편집자료/기획안/용어.txt`(한 줄에 하나)로 둔다
  2. `lf transcribe 촬영본/<사운드 또는 메인캠> 편집자료/전사/전사.json --glossary 편집자료/기획안/용어.txt` (백그라운드, 5분 분량이면 1~2분)
  3. `lf transcript_lines 편집자료/전사/전사.json 편집자료/전사/전사본_초안.txt` → 사람이 읽을 수 있는 줄 단위 초안. 단어 사이에 띄어쓰기를 넣어 준다(단어 json을 그냥 이어 붙이면 띄어쓰기가 사라진다)
  4. 화자 구분용 화면 시트(4초 간격 6×5):
     `ffmpeg -i <원본> -vf "fps=1/4,scale=480:-1,drawtext=text='%{pts\:gmtime\:0\:%M\\\\\:%S}':x=8:y=8:fontsize=28:fontcolor=yellow:box=1:boxcolor=black@0.6,tile=6x5" -q:v 4 편집자료/시트/sheet_%02d.jpg` (`ffmpeg -i 촬영본/<메인캠> …`)
     (Fontconfig 경고가 떠도 라벨은 찍힌다)
  5. 클로즈업·투샷·손짓으로 화자를 정하고, 긴 독백 안에서 화자가 바뀌는 지점은 단어 타임스탬프로 찾는다. 화면만으로 정한 화자는 `※`, 안 들리는 말은 `[?]`로 표시한다.
- 최종 형식(한 줄에 하나): `[mm:ss] 화자: 대사` (1시간 넘으면 `[h:mm:ss]`). 맨 위에 기준 파일, 화자 표기 규칙, 카메라가 여러 대면 어느 파일 기준 TC인지 적는다.
- **기획안 검수**: 기획안의 고유명사(이름, 회사, 용어)·숫자로 오타를 고치고, 고친 것과 의심 가는 것을 `편집자료/전사/검수.md`에 `| TC | 전사 | 고침 | 근거(기획안 쪽수·항목) |` 표로 남긴다. 출연자 이름을 모르면 옷·위치로 임시 이름을 붙이고 "확인 필요"에 올린다.

## STEP 3. 기획안·레퍼런스 ↔ 실제 발언 대조
전사본을 끝까지 읽고 표로 만든다:
`| 기획 포인트 / 레퍼런스 비트 | 결과(기획대로 나옴 / 다르게 나옴 / 새로 나옴 / 안 나옴) | 원본 TC | 메모 |`

## STEP 4. 소재 후보 · 제외 구간
- 후보: `TC / 화자 / 한 줄 요약 / 쓸모(자격·반전·원인·감정 피크·웃음·명언·시연) / 콜드오픈·숏폼 후보 표시`
- 제외: NG와 다시 찍은 부분(마지막 테이크만 사용), 제작진 발언, 잡담, 출연자가 빼 달라고 한 말, 화면 문제(흔들림·초점·소품·스태프 프레임 인)
- 제외 구간은 자동 검증용으로 `mm:ss-mm:ss, …` 형식으로 따로 적는다.

## STEP 5. 흐름 승인 — 여기서 반드시 멈추고 확인을 받는다 (= 문 ①의 앞부분)
보여 줄 것:
- 핵심 메시지 한 줄
- 콘텐츠 가설 1개
- 골격 매핑 표: 레퍼런스 골격 비트 → 우리 장 → 쓸 원본 TC (빈 비트는 대체 장치)
- 장 구성 한 줄씩 + 콜드오픈 안(3~5컷) + 예상 길이
그리고 "이대로 갈까요?"라고 묻는다.

레퍼런스가 없을 때의 기본 골격:
- 인터뷰: 콜드오픈(위기·결론) → 숫자로 보여 주는 소개 → 원래 어떤 사람 → 전환점 → 시행착오 → 지금의 방법 → 태도·철학 → 앞으로/CTA
- 강의·솔로토크: 콜드오픈(프레임 선언) → 고백·사건 → 개념 이름 붙이기 → 원칙 1·2·3 → 사례로 증명 → 정리 → CTA
- 브이로그: 콜드오픈(하이라이트) → 오늘의 미션 → 시간대별 챕터 → 갈등·반전 → 회고 → 아웃트로
- 대담·패널: 콜드오픈(가장 센 의견 충돌) → 주제 제시 → 쟁점 1·2·3(입장 → 반론 → 정리) → 결론·한마디씩
- 리뷰·시연: 콜드오픈(결과물) → 문제 → 시도·시연 → 비교·결과 → 추천/주의
- 악플읽기(한살차이 레퍼런스에서 뽑음): 콜드오픈(가장 센 대사 + 웃긴 장면) → 짧은 인트로 → 댓글 낭독 → 반박·해명 → 개그로 숨 돌리기 → 직접 증명하는 장면 → 진지한 메시지 → 아웃트로(감사·다음 편·댓글 요청). 무거운 비트 바로 앞이나 뒤에는 웃긴 비트를 둔다.

## STEP 6. 구성안 + 예상 스크립트 (승인 뒤)
`편집자료/구성안_1차.md` 형식 — **스크립트가 읽는 형식이니 지킨다**:
- 맨 위: 원본 파일과 TC 기준, 포맷, 레퍼런스, 예상 길이(목표 길이), 자막 표기 규칙
- `## 이 영상의 핵심 메시지` / `## 콘텐츠 가설` / `## 레퍼런스에서 가져온 것`
- `## 0. 콜드오픈 (완성본 0:00~0:15) {비율 1.0}` + 표 `| 순서 | 원본 TC | 화자: 대사 | 역할 | 화면 |` (TC 칸은 `mm:ss~mm:ss`)
- `## N. <장 제목> (완성본 시작~끝) — 이 장이 하는 일`
  - 맨 앞이 `- mm:ss~mm:ss`인 줄만 길이 계산에 들어간다. 세부 메모는 들여쓴 `  - `로 쓰고, 그 줄은 TC로 시작하지 않는다(같은 구간을 두 번 세지 않도록)
  - 자막·그래픽 카드처럼 원본이 없는 항목은 `- ⏱ 3초 …`로 쓴다
  - 압축이 심한 장은 제목 끝에 `{비율 0.7}`처럼 비율을 붙인다(기본 0.86, 컷이 촘촘하면 0.8)
  - 이미 컷편집된 촬영본은 더 줄일 침묵이 거의 없다. 비율을 1.0에 가깝게 잡는다(악플읽기_댓글1: 0.86으로 4:34 추정 → 실제 4:53)
  - 기호: [강조] 자막 문구 / ◆ 자료 / ▷ 설명자막 / ※ 편집 메모 / ⚠️ 화면 문제 / ♪ 음악
- 끝에 `## 숏폼 후보` / `## 목표 길이로 줄이려면` / `## 확인 필요` (`##` 뒤에 번호가 없는 장은 계산에서 빠진다)
- 원본 순서가 아니라 메시지와 골격 순서로 재배치한다. 장 제목의 시간은 완성본 누적 추정, 항목의 TC는 원본 기준.

예상 스크립트:
`lf plan_script 편집자료/구성안/구성안_1차.md 편집자료/전사/전사본.txt 편집자료/구성안/예상스크립트_1차.txt`
— 구성안 순서대로 `[완성본 추정 시각] (원본 TC)` 다음에 `화자: 대사` 줄을 넣는다. 화자가 "스태프·제작"이면 뺀다.

## STEP 7. 자동 검증 — 넘기기 전에 꼭
`lf plan_verify 편집자료/구성안/구성안_1차.md 편집자료/전사/전사본.txt "<STEP 4 제외 구간>"`
- 장별·전체 예상 길이
- [전사 줄 없음] / [전사 범위 밖] / [역순/0초] / [제외 구간 침범] / [구간 겹침](콜드오픈 재사용이면 "정상"으로 표시)
- 참고: 본편에서 안 쓴 원본 구간 → 의도적으로 뺀 곳인지 확인
